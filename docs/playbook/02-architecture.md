# Prompt 2: Architecture (approved)

The playbook assumes a GoHighLevel AI Studio native SSR master template (TanStack Start, Nitro).
There is no master template for this site. Per CLAUDE.md the approved architecture is a static,
pre-rendered site, and this is treated as approved. No framework conversion was attempted.

## Stack
- **Pages:** real HTML files, pre-rendered at build time. Every title, description, canonical, Open
  Graph tag, H1, body copy and JSON-LD block is in the initial HTML response. This is the static
  equivalent of "raw server HTML / SSR".
- **Build:** `build.py` (Python 3, Jinja2 3.1, PyYAML). Writes to `dist/`, which is committed.
- **Hosting:** Netlify, `netlify.toml` with `publish = "dist"` and no build command.
- **Hydration / router:** none needed. Navigation is plain links between static pages, so every
  route starts at the top, back/forward and refresh are native, and direct loads of nested routes
  are just files. `src/static/js/site.js` only adds the mobile menu, submenus and the EN/ES toggle;
  the site works without it.

## Centralized configuration
- `src/data/site.json`: business identity, phone (display + tel), CTAs, form name and options,
  social URLs (empty = hidden), analytics IDs (empty = not loaded), navigation, footer links, the
  services, guides and cities (slug, name, summary, card image, region).
- Header, footer, hero, FAQ, call/form section and breadcrumbs are shared partials in
  `src/templates/partials/`. Reusable blocks are macros in `src/templates/macros.html`.
- Structured data is generated centrally in `build.py` (`Builder.jsonld`) from site.json + each
  page's front matter: one `@graph` per page with Organization, WebPage/AboutPage/ContactPage,
  BreadcrumbList, Service (services and cities), Article (guides) and FAQPage (from the same `faqs`
  data that renders the visible "Common questions" block).
- `sitemap.xml` and `robots.txt` are generated by the build from the page list (noindex pages
  excluded).

## Routes
File-based: `src/pages/<path>.html` → `/<path>/` (pretty URLs with trailing slashes).
`src/pages/index.html` → `/`, `src/pages/404.html` → `/404.html` (served by Netlify for unknown paths).
Old URLs 301 through `src/static/_redirects` (copied into dist/).

## Forms
Native Netlify Forms. The form markup is in every built page's HTML (`data-netlify="true"`, name
`houston-powerwashing-contact`, honeypot `bot-field`, action `/thank-you/`). It is never lazy-loaded
or injected by script, so it renders on first load and after any navigation.

## Commands
| Task | Command |
|---|---|
| Build | `python3 build.py` |
| Rule, SEO and link checks | `python3 scripts/check.py` |
| Similarity check | `python3 scripts/similarity.py` |
| Local preview | `npx http-server dist -p 8080` |
| Screenshots / overflow / console | `NODE_PATH=$(npm root -g) node scripts/shot.js <url> <prefix>` |
| Browser QA suite | `NODE_PATH=$(npm root -g) node scripts/qa.js` |

There is no typecheck or lint step in the project (no TypeScript); `check.py` stands in for the
playbook's checks. No hard blockers.
